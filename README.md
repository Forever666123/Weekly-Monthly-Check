## 定时任务

两条任务已经建好（用 cron，时间是 **UTC**）：

| 任务 | 悉尼时间 | cron (UTC) | 首次生效 | trigger id |
| --- | --- | --- | --- | --- |
| 周检查 | 每周日 20:00 | `0 9 * * 0` | 2026-10-04（此前触发也不发） | `trig_013VBxzHyKHR4mZvrTnyqjEZ` |
| 月检查 | 每月 1 号 20:30 | `30 9 1 * *` | 2026-11-01（此前触发也不发） | `trig_01EzrgHFhw2z53HFdgBiMGqF` |

每次触发会开一个全新会话，跑完就结束，互不影响。

**时区**：cron 只认 UTC，不跟随夏令时。`09:00 UTC` = 夏令时（AEDT，10 月初到次年 4 月初）悉尼 20:00，= 标准时（AEST）悉尼 19:00。两种情况下悉尼日期都还在同一天（周日 / 1 号），所以周数、月份、补发判断都不受影响，只是南半球冬天那几个月会早一小时到。

**规范怎么生效**：触发出来的会话会 clone 本仓库的默认分支（当前是 `claude/zen-maxwell-5hu700`），先读对应的 SKILL.md，以它为准；读不到才退回 trigger 里内嵌的同一份规范副本。所以改 SKILL.md 并推到默认分支，下一次邮件就会按新规范发。如果改动比较大，顺手也更新一下 trigger 里的内嵌副本（`update_trigger` 的 prompt）。

**Gmail**：建任务的接口不能附带 connector，建完有警告说触发出来的会话拿不到 `mcp__Gmail__send_message`。已在同一环境实测过（2026-09-14 开了一个新会话，成功发出自检邮件），这个环境的新会话是拿得到 Gmail 的。万一某次没收到邮件，第一件事就是去 claude.ai 的 Routines 里确认任务上挂着 Gmail。

## 日期口径

- 第 1 周 = 2026-09-28 至 2026-10-04。某个周日 X 的周数 = (X − 2026-10-04) ÷ 7 + 1。
- LeetCode 累计基准 T(n)：n ≤ 9 → 5n；10 ≤ n ≤ 22 → 45 + 15(n−9)；n ≥ 23 → 240 + 5(n−22)。
  校验点：T(4)=20，T(9)=45，T(13)=105，T(18)=180，T(22)=240。
- 补跑：触发日比该周的周日（或该月 1 号）晚 2 天以上，主题前加「(补发)」。
